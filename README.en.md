# llm-passthrough

A tiny passthrough reverse proxy for [OpenRouter](https://openrouter.ai) (and any other LLM API) in regions where it is blocked. Official `nginx:alpine` image, no builds, ~10 MB RAM. Sits behind your existing reverse proxy — Pangolin, Caddy, Nginx Proxy Manager, Traefik or plain nginx.

**v0.4.2** · beta · [MIT](LICENSE)

> ⚠️ Bypassing regional restrictions may violate the upstream ToS — account risk is on you. Keep your proxy domain private, keep your API key local.

## How it works

```
app ──► https://openrouter.example.com/<SECRET_PREFIX>   (TLS at your reverse proxy)
          └─► this container (plain HTTP, strips the prefix)
                └─► https://openrouter.ai   (SNI/Host rewritten)
```

- Apps only change their Base URL; the API key is passed through and never stored — the proxy is stateless
- Everything outside `/<SECRET_PREFIX>/` is a hard 404
- SSE streaming is unbuffered; 600 s timeouts for long LLM answers

## Quick start

```bash
git clone https://github.com/ptath/llm-passthrough.git
cd llm-passthrough
./install.sh
```

`install.sh` creates `.env` with a random 32-char `SECRET_PREFIX` on first run and starts the container (listening on `127.0.0.1:8080`). Custom prefix: `SECRET_PREFIX=my-long-prefix ./install.sh`, or edit `.env` later and run `docker compose up -d`.

## One-command install

On a root-accessible server:

```bash
curl -fsSL https://raw.githubusercontent.com/ptath/llm-passthrough/main/install.sh | bash
```

The installer checks docker, probes which APIs are reachable from the machine, asks what to proxy, generates the secret prefix and a subdomain, detects your reverse proxy (Pangolin/NPM/Traefik/Caddy in docker) and writes `compose.override.yml` for you. Answer `y` to "Add another proxy?" to serve several APIs from one server — each gets its own container, prefix and subdomain. Rerunning the installer offers Enter = keep (rebuild from `instances.conf`, zero questions) or `r` = full reconfiguration. `--lang en` switches the dialog language (Russian by default).

### Where to find your SECRET_PREFIX

It is printed at the end of `install.sh` and stored in `.env`:

```bash
grep SECRET_PREFIX .env
```

Apps use a Base URL like `https://your.domain/<SECRET_PREFIX>` (they append `/api/v1` themselves). If `.env` is lost but the container still runs, recover it: `docker compose exec passthrough env | grep SECRET_PREFIX`.

## Variables

| Variable | Default | Description |
|---|---|---|
| `SECRET_PREFIX` | generated by install.sh | required; part of your URLs |
| `UPSTREAM_URL` | `https://openrouter.ai` | upstream to forward to |
| `UPSTREAM_HOST` | `openrouter.ai` | SNI/Host for the upstream |
| `BIND_IP` / `BIND_PORT` | `127.0.0.1` / `8080` | debug listener address; for a proxy on ANOTHER machine use `0.0.0.0` and an open port |

Point at another API by changing two variables — paths are forwarded as-is, so OpenAI, Anthropic and friends all work the same way. In a multi-provider setup `.env` belongs to the first instance; the rest are written into the generated `compose.override.yml`, with state in `instances.conf` — reconfigure by rerunning `install.sh` (Enter = keep, `r` = full reconfigure), not by hand.
