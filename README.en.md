# openrouter-passthrough

A tiny passthrough reverse proxy for [OpenRouter](https://openrouter.ai) (and any other LLM API) in regions where it is blocked. Official `nginx:alpine` image, no builds, ~10 MB RAM. Sits behind your existing reverse proxy — Pangolin, Caddy, Nginx Proxy Manager, Traefik or plain nginx.

**v0.1.0** · beta · [MIT](LICENSE)

> ⚠️ Bypassing regional restrictions may violate the upstream ToS — account risk is on you. Keep your proxy domain private, keep your API key local.

## How it works

```
app ──► https://openrouter.example.com/<SECRET_PREFIX>   (TLS at your reverse proxy)
          └─► this container (plain HTTP, strips the prefix)
                └─► https://openrouter.ai   (SNI/Host rewritten)
```

- Apps only change their Base URL; the API key is passed through and never stored — the proxy is stateless
- Everything outside `/<SECRET_PREFIX>/` is a hard 404
- SSE streaming is unbuffered; 600 s timeouts for long LLM answers

## Quick start

```bash
git clone https://github.com/ptath/openrouter-passthrough.git
cd openrouter-passthrough
./install.sh
```

`install.sh` creates `.env` with a random 32-char `SECRET_PREFIX` on first run and starts the container (listening on `127.0.0.1:8080`). Custom prefix: `SECRET_PREFIX=my-long-prefix ./install.sh`, or edit `.env` later and run `docker compose up -d`.

## Variables

| Variable | Default | Description |
|---|---|---|
| `SECRET_PREFIX` | generated by install.sh | required; part of your URLs |
| `UPSTREAM_URL` | `https://openrouter.ai` | upstream to forward to |
| `UPSTREAM_HOST` | `openrouter.ai` | SNI/Host for the upstream |

Point at another API by changing two variables — paths are forwarded as-is, so OpenAI, Anthropic and friends all work the same way.
